EISOL Support Sync — User guide

EISOL Support Sync connects a Jira Cloud site to an Intercom workspace. Support teammates create a Jira issue from an Intercom conversation, and project administrators can link more conversations to the same issue. New messages in a linked conversation are copied to the issue as comments, and Jira comments and status changes appear in the conversation as internal notes. When an issue is done, its conversations can go back to the inbox. The app runs entirely on Atlassian Forge.

See pricing.

Why the app asks for access to Intercom

When you connect Intercom, the app asks for these permissions, and uses them only for what this page describes:

  • Read conversations: to read a conversation's title and first message when an issue is created from it; every five minutes, the list of conversations changed in the workspace (for conversations that are not linked, the app uses only their ID and update time) and the new messages of linked conversations; and the title, customer and state of linked conversations, for the panel next to an issue and for putting them back in the inbox.
  • Write conversations: to add internal notes to linked conversations, and to put a closed or snoozed conversation back in the inbox when its issue is done (on by default; you can turn it off).
  • Read admins: to know which teammate approved the connection. The app's notes are written in that teammate's name.
  • Read and write data connectors: to create the data connector "Create Jira issue" in your workspace, which calls this Jira site when a teammate runs it.

The app does not read your contacts' profiles, companies, articles or other data, and it does not send messages to your customers. Apart from putting a conversation back in the inbox when its issue is done, everything it writes to conversations is an internal note. See section 11 and the privacy policy.

Before you start

  • You need to be a Jira administrator to set the app up, and an Intercom teammate who can install apps in the workspace to approve the connection.
  • The app's internal notes appear in Intercom under the name of the teammate who approved the connection. Choose a teammate who will stay in the workspace, or a shared support account.
  • Your teammates create issues with an Intercom data connector. Running data connectors from the inbox depends on your Intercom plan and seats.
  • Each Jira site connects one Intercom workspace. Connect a workspace to one Jira site only: each site that connects it adds its own data connector Create Jira issue, and your teammates would see one for each site.
  • The app works with Intercom conversations. Intercom tickets are not supported in this version.

1. Install the app

A Jira administrator installs EISOL Support Sync from its Atlassian Marketplace listing, or in Jira under Apps → Explore more apps. The app's settings page is then under Settings → Apps → EISOL Support Sync. You can try the app free of charge before you buy.

2. Connect Intercom

  1. In Jira, go to Settings → Apps → EISOL Support Sync.
  2. Choose where your Intercom workspace is hosted: United States (you sign in at app.intercom.com), Europe (app.eu.intercom.com) or Australia (app.au.intercom.com).
  3. Select Connect Intercom. Jira asks you to confirm that you are opening an outside page; continue, and Intercom's page opens in a new tab. Sign in if asked, check the permissions and the workspace, and authorize the app.
  4. Intercom sends you back through EISOL's page https://connect.eisol.jp/intercom/, which passes the approval to your Jira site. The page that opens shows a confirmation code and the Jira site it is for. Return to the app's settings page on that site, enter the code under Enter the confirmation code within 10 minutes, and select Finish connecting. The settings page then shows Connected to and the workspace's name.

Nothing is connected until the code is entered. The code ties the approval in Intercom to an administrator of this Jira site, so a connection link that was forwarded, or sent to you by someone else, cannot connect a workspace by itself. If a colleague approves in Intercom for you, ask them for the code on their page. Enter a code only on the settings page of the site named on that page, and never give a code to someone who asks for it.

3. Choose where new issues go

Under Where new issues go, enter the key of the Jira project for new issues, such as SUP, and select Save. The app uses the project's Task issue type, or its first issue type that is not a subtask, and shows it: "Issues are created in SUP as Task." The app creates issues with its own Jira rights, so your teammates in Intercom do not need a Jira account.

4. Set up the data connector

Under Data connector, select Set up the data connector. The app creates the data connector Create Jira issue in your Intercom workspace and makes it live. When a teammate runs it, Intercom sends only the conversation's ID to this Jira site, with a secret that the app set in the connector, and gets back only the issue's key and address. Your teammates enter nothing. The connector is for teammates only: the app creates it with Fin's use turned off and with customer authentication off, so it runs on any conversation, including those with visitors who have not verified their identity. Nothing is returned to the customer.

Set it up again gives the connector a new secret, and sets its address, its Authorization header, customer authentication (off) and its state (live) again. If the connector was deleted in Intercom, it creates a new one. It does not undo other changes, such as to the request body or to Fin's use. Do not edit the connector in Intercom, and leave Fin's use of it off. If it was changed, delete it in Intercom and select Set it up again.

5. Create a Jira issue from a conversation

In the Intercom inbox, open the conversation and run the data connector Create Jira issue: press ⌘K (Ctrl+K on Windows), choose Use a data connector, and then Create Jira issue.

The app then:

  • creates an issue in the chosen project. Its summary is the conversation's title (up to 250 characters) or, when it has none, the first line of the conversation's first message (up to 120 characters); when the conversation has neither, or Intercom cannot be read at that moment, "Intercom conversation" and the conversation's number. Its description links to the conversation and quotes the first message (up to 2,000 characters).
  • links the conversation to the issue, and adds an internal note to the conversation with a link to the issue.

Running Create Jira issue again on the same conversation creates no second issue and adds no second note: Intercom gets the key of the issue already linked. Intercom waits up to 30 seconds for the answer. Recent issues from conversations on the settings page lists the last ten issues created.

6. Link more conversations to an issue

When several customers report the same problem, link their conversations to one issue. Open the issue in Jira and open the Intercom panel:

  • The panel says how many conversations are linked and how many customers they come from, and lists the ten most recently updated (of up to 60), with their title or first line, their customer, their state and when they were last updated. Each one opens in the Intercom inbox.
  • A project administrator can paste a conversation's address from the Intercom inbox, or its number, and select Link. The conversation gets an internal note with the issue's key, summary and link, and its new messages are copied to the issue from then on.
  • A project administrator can select Unlink on a conversation. The comments and notes already written stay.

A conversation is linked to one issue at a time. To move it, unlink it from its issue first. Everyone who can see the issue in Jira sees the panel's list, including the customers' names and the first lines of their conversations.

7. What syncs and when

Settings under Sync of linked conversations choose what is copied. Select Save the sync settings after a change.

Intercom → Jira, every five minutes. The app looks for conversations that changed, and copies the new messages of linked conversations to their issue as comments:

  • Customer messages: on by default.
  • Teammate replies to the customer: off by default.
  • Internal notes: on by default.

Each comment starts with a line such as "From Intercom · customer message · Jane Doe · 2026-12-01 09:30 UTC · conversation 123", which links to the conversation. The comments are written by the app. Messages from before the link, messages from Fin, bots and workflows, and the app's own notes are not copied. Attachments are not copied: the comment says how many there are, and they stay in Intercom.

Jira → Intercom, at once. Jira tells the app about each change:

  • Jira comments, as internal notes: on by default. The note starts with "From Jira", the issue key, the comment's author and time, and links to the comment. Comments restricted to a role or group, comments by apps (Jira Automation included) and the app's own copies are not sent.
  • Status changes, as internal notes: on by default, for example "Status: In Progress → Done".
  • Put the conversation back in the inbox when its issue is done: on by default. When the issue moves to a status in the Done category, its closed or snoozed conversations are opened again, with a note that says why, even when status notes are off.

Edits and deletions of messages, notes and comments are not followed in either direction. When an issue is deleted, the app unlinks its conversations. Each Jira comment is sent once to each conversation.

When something fails. If Jira or Intercom is busy or cannot be reached, the app tries again: a message on the next run, and a note every five minutes for a day. Notes for Intercom not written yet on the settings page shows how many are waiting. When a failure may have come after the copy was made, the app looks for the copy before it writes it again, so it is not made twice. Other failures are listed under Recent problems.

Last look at Intercom on the settings page shows when the app last looked, how many changed conversations it found and how many messages it copied.

8. Limits

  • One Intercom workspace for each Jira site.
  • A conversation is linked to one issue. An issue sends its comments and status changes to up to 200 linked conversations.
  • The panel reads up to 60 of an issue's linked conversations: it counts their customers and lists the 10 most recently updated of them.
  • Messages from before a conversation was linked are not copied, and edits and deletions of messages, notes and comments are not followed.
  • Attachments are not copied. Very long messages and comments are shortened, with a line that says the whole text is in the other product.
  • Changes in Intercom are copied every five minutes, not at once. Each run starts no new work after about 200 seconds, so a large backlog is copied over several runs.
  • Intercom conversations only; Intercom tickets are not supported.

10. Disconnect, delete data and uninstall

  • Disconnect on the settings page stops the sync and the data connector, and deletes the app's Intercom token. The links and settings are kept, so connecting the same workspace again with Connect again continues with them. Disconnecting does not remove the app from the Intercom workspace, because the same workspace may be connected to other Jira sites. To remove it, go to Settings → API tokens in Intercom and select Revoke on the app's OAuth token.
  • After a disconnect, Use another account and then Forget and continue make the app forget everything it keeps for this site: the workspace, the region, the data connector's record and secret, the project, the sync settings, the links and sync positions, the notes waiting to be written, the recent issues and the recent problems. The data connector Create Jira issue stays in Intercom and answers "Not authorized." from then on, so delete it in Intercom's data connector settings. Set up the data connector later creates a new one.
  • Disconnecting makes the app forget its token, but Intercom keeps the app's access to the workspace until the app's token is revoked in Intercom (Settings → API tokens → Revoke).
  • While the app's license is not active, the sync and the data connector stop, and Intercom cannot be connected and conversations cannot be linked, until the license is renewed. Disconnecting and deleting the app's data still work.
  • Issues, comments and notes already written stay in Jira and Intercom. Delete them there if you no longer need them.
  • To stop using the app: select Disconnect, then Use another account. In Intercom, revoke the app's token under Settings → API tokens and delete the data connector Create Jira issue. Then uninstall the app from Jira. Atlassian deletes the app's remaining stored data after its retention period.

11. Data and privacy

The app runs on Atlassian Forge, and EISOL runs no servers for it. Conversation content goes from Intercom to your Jira site, and Jira comments and status changes go to your Intercom workspace, through Forge.

  • What the app reads from Intercom: every five minutes, the list of conversations changed in the workspace (for conversations that are not linked, it uses only their ID and update time); the conversations it creates issues for or that are linked, including their messages and the names of their authors; for the panel, the title, first message, starting customer's name, state and update time of linked conversations, and the IDs of their customers; and the connecting teammate's ID (read when the app writes, not kept) and the workspace's ID, name and region.
  • What it writes to Jira: issues (summary, a description with the first message and a link to the conversation) and comments with the copied messages and their authors' names. Each issue it creates and each comment it copies also carries a hidden Jira property (eisol-intercom) with the conversation's ID and, for a comment, the message's ID, which the app uses to avoid duplicates.
  • What it writes to Intercom: internal notes with Jira comments and their authors' names, status changes, issue keys and links and, when a project administrator links a conversation, the issue's summary; reopening closed or snoozed conversations when their issue is done (if that setting is on); the data connector Create Jira issue, which holds this Jira site's app address and a secret; and, each time the connector runs, the issue's key and address in its answer.
  • What it keeps in Forge: the workspace's ID, name and region and when it was connected; the Intercom token and the data connector's secret (in Forge's encrypted secret storage); the data connector's ID and state; the project and sync settings; the links between conversations and issues; the IDs and times of the messages already looked at and of the Jira comments and status changes already sent; Jira changes waiting to be written; the last ten issues created and the last 30 problems. Apart from Jira's answers in short error messages, it keeps no message text and no people's names, email addresses or account IDs.

See the privacy policy, the Data Processing Addendum and support and service levels.
