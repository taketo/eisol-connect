EISOL Time Sync — User guide

EISOL Time Sync copies time entries from Toggl into Jira worklogs. Each worklog is written in the name of the person who tracked the time, after that person confirms their link once. When an entry changes or is deleted in Toggl, the worklog follows. The app runs entirely on Atlassian Forge.

See pricing.

Before you start

  • You need to be a Jira administrator to set the app up.
  • The app works with the new Toggl (toggl.com), which Toggl previously called Toggl 2.0 and Toggl Focus. Toggl Track is not supported yet.
  • You need the API key of a Toggl admin of your workspace. The app reads the team's time through Toggl's reports, so the key's user must be able to see the time of the whole team, on a Toggl plan that includes reports.
  • Each person whose time is copied needs a Jira account on your site, with permission to log work on the issues their time goes to. Jira's time tracking must be on.

1. Connect Toggl

  1. In Toggl, open Settings → API key and copy the key. Use the key of a Toggl admin.
  2. In Jira, go to Settings → Apps → EISOL Time Sync.
  3. Paste the key under API key of a Toggl admin and select Connect. The app checks the key with Toggl and shows the workspace it belongs to.
  4. Copying starts with the entries that start today (UTC). To start from an earlier day, enter it under Copy the entries that start on or after this day and select Save. The app reads at most the last 30 days again.

The app keeps the key in Forge's encrypted storage and never shows it again. Keys of the new Toggl can expire: when Toggl refuses the key, copying stops and the settings page asks for a new one. Select Paste a new key to replace it.

2. Link people

Time is copied only for people who are linked and have confirmed.

  1. On the settings page, under People, select Find people with time in the last 30 days. The app lists each Toggl person who tracked time in that period.
  2. For each Toggl person, pick their Jira person. The state changes from Not linked to Waiting for the person.
  3. Each linked person confirms on their own page (section 3). The state then shows Confirmed.

To link someone else, select Unlink and pick again. A new link has to be confirmed again. Worklogs already made in the first person's name stay theirs: the app no longer changes or removes them, and copies the entries again for the new person when they change in Toggl.

3. Each person confirms

Each person opens Apps → EISOL Time Sync in Jira's top menu.

  • Under Is this you?, the page shows the Toggl person an admin linked to them. Yes, this is me starts copying their time. No, this is not me removes the link, so an admin can link the right person.
  • After confirming, the app copies the person's entries since the copy start (from the last 31 days at most), usually within five minutes.
  • Stop copying my time stops copying. Worklogs already in Jira stay, and the app no longer changes or removes them.

The page also shows the person's recent copies and their Unassigned time entries (section 5).

4. Which issue an entry goes to

  1. An issue key in the description. The first key in the entry's description, anywhere in the text, for example Fix login ABC-123.
  2. A project rule. Without a key, the entry goes to the issue of its Toggl project's rule. Under Project rules, pick a Toggl project (the list fills in when you find people), enter an issue key and select Add the rule.
  3. The person's choice. Without either, the entry is not copied. It waits under the person's Unassigned time entries (section 5).

When the description or the project changes in Toggl, the worklog moves to the new issue.

5. Choosing an issue for an unassigned entry

On their own page, a confirmed person sees their stopped entries from the last 31 days that have no issue key or project rule. Each line shows the entry number, start time and length; descriptions are not stored by the app, so they are not shown.

  1. Select Choose issue on the entry.
  2. Type an issue key or words from its title under Issue key or title, and select Search. Only issues the person can see are found.
  3. Pick the issue under Jira issue and select Queue copy. The app checks that the person can log work on it.

The entry is copied in the next run, usually within five minutes. A key added to the description in Toggl, or a project rule, takes precedence over the choice.

6. How copying works

  • Every five minutes, the app reads the entries changed in Toggl since its last look, and copies each stopped entry of a confirmed person.
  • The worklog's start time and time spent come from the entry. Jira keeps whole minutes, so seconds are rounded to the nearest minute. Entries shorter than half a minute, and running timers, are not copied; a timer is copied when it stops.
  • The entry's description becomes the worklog's comment (up to 1,000 characters). Everyone who can see the issue's work log can read it.
  • When an entry changes in Toggl, its worklog changes too. When it is deleted in Toggl, its worklog is removed (section 7).
  • The app changes and removes only worklogs it created. Each one carries a hidden mark naming its Toggl entry.
  • If someone deletes a copied worklog in Jira, the app copies the entry again only when it changes in Toggl.
  • The app uses part of Toggl's hourly request quota: about 16 to 20 requests an hour, plus one for each person and day with deleted or chosen entries. If the quota is used up, the app waits until Toggl resets it and then goes on.
  • Read the last 30 days again (settings page) reads the entries changed in the last 30 days again, so that entries a new rule or a newly confirmed person covers are copied.

7. Entries deleted in Toggl

Toggl does not say when an entry is deleted. Every 15 minutes, the app reads the entries of the last seven days. When two of these checks in a row miss a copied entry, the app removes its worklog, so a deletion reaches Jira in about 15 to 35 minutes. Before removing one, it reads all of that person's entries around that day once more.

  • If more than 20 copied entries seem to be gone at once, and they are more than half of the entries copied in the last seven days, the app removes nothing and lists a problem: that usually means a problem with the key or the workspace, not real deletions.
  • Entries deleted more than seven days after they started are not followed: their worklogs stay.
  • When we removed a person from a Toggl workspace in our tests, their entries stayed in Toggl's reports, so their worklogs stayed too.

8. Disconnecting and resetting

  • Disconnect deletes the key and stops copying; the settings page shows Disconnected. The people, rules and links stay, so pasting a key of the same workspace goes on from where the app stopped.
  • Reset… then Reset the app forgets the key, the people, the rules, the choices and which entries were copied. Worklogs already in Jira stay. If a copy is running at that moment, the key and settings go at once and the page asks you to select Reset the app again a few minutes later. If the same people are linked and confirm again, the app finds the worklogs it made by their mark, and does not copy the entries twice.
  • When you uninstall the app from Jira, Atlassian deletes its stored data, the key included, after its retention period. Worklogs stay in Jira.

10. Data and privacy

The app runs on Atlassian Forge, and EISOL runs no servers for it. It reads time entries from your Toggl workspace and writes nothing to Toggl. It keeps the Atlassian account IDs of linked people, reports them to Atlassian once a week as Atlassian requires, and erases them when Atlassian reports an account as closed. See the privacy policy, the Data Processing Addendum and support and service levels.
